# Plano de Implementação: GGUF Fatia 1 (Qwen2 com F16, Q8_0 e Q4_0)

**Data:** 2026-10-16  
**Estado:** Em elaboração

## Objetivo da Fatia 1

Implementar suporte ao formato GGUF para arquitetura Qwen2 com os tipos de dados F16, Q8_0 e Q4_0, incluindo leitura de arquivos GGUF, quantização específica, integração com modelos existentes e verificação de paridade.

## Decisões do Autor Aplicadas

- Escala half inline vira float separada (Q4_0/Q8_0): Q4_0 de 18 para 20 bytes por bloco (+11%), Q8_0 de 34 para 36
- mmap por tensor (evita limite de 2GB)
- F16 alargado para F32 ao carregar (documentar custo de memória)
- SentencePiece fora (apenas gpt2/BPE de byte)
- Kernel novo Panama F32xQ8 em PanamaTensorOperations (sem I8xQ8)
- Ordem do plano: leitor GGUF + escritor de teste, kernel Panama F32xQ8, paridade dos pesos, tokenizer, ponta a ponta
- Tratamento de combinações sem kernel: delegar ao Panama ou lançar erro claro (decisão baseada em como NativeSimdTensorOperations trata combinações sem kernel)

## Tarefas TDD (Ordem de Execução)

Cada tarefa deve ser implementada seguindo TDD: escrever teste primeiro, depois implementação mínima para passar o teste, refatorar, commitar.

## Considerações de Implementação

### Variáveis de Ambiente para Testes Opt-in
- Testes que baixam modelos GGUF devem ser opt-in por variável de ambiente (similar a `SMOKE_MODEL=1`)
- Usar `curl -L -C -` para download com retomada
- Modelos de teste: Qwen/Qwen2.5-0.5B-Instruct-GGUF (Apache-2.0)

### Build e Testes
- Build: `export JAVA_HOME=$HOME/.sdkman/candidates/java/25.0.3-amzn; ./mvnw -B ... package`
- Excluir `-Dtest='!TestSample'` conforme instruções
- Não usar `git reset --hard`; editar arquivos CRLF por script Python em bytes

### Commits
- Commits pequenos e frequentes, cada um contendo uma unidade de trabalho clara
- Mensagens de commit em português europeu
- NUNCA adicionar trailers (Co-Authored-By, Claude-Session, "Generated with") ou atribuição de IA
- Não fazer push, tags nem releases

### Riscos Conhecidos e Mitigações
1. **Ordem das dimensões:** Confirmar com tensor real antes de escrever `GgufRepack` (mitigação: teste de paridade dos pesos)
2. **Tokenizer:** Reproduzir exatamente o do tokenizer.json (mitigação: teste de paridade do tokenizer)
3. **Tokens especiais:** Converter para *added tokens* para segmentação correta do template de chat
4. **Template de chat:** Entrar no `PromptSupport` como no `tokenizer_config.json`
5. **Embeddings partilhados:** Lidar com ausência de `output.weight` quando embeddings são partilhados
6. **Arquivos grandes:** Mapear por tensor (não assumir tamanho pequeno)
7. **Falso positivo de correção:** Verificação contra referências, não apenas inspeção visual
